# MediaFlow MVP 管理员 Web 体验设计

> 日期：2026-07-16
> 状态：书面设计与中保真原型已完成 M1.4 人工验收，并于 2026-07-16 按 M1.5 整体确认重定标
> 适用范围：M1.4 信息架构、核心流程、状态、设计系统基础和中保真原型；M1.5 需求与交互一致性修订

## 1. 文档目的

本文依据已验收的 [MVP 范围、需求与验收场景](../product/mvp-scope-requirements.md)、[MVP 用户、问题与领域语言](../product/mvp-user-problem-domain-language.md)、[竞品与工作流研究](../product/mvp-competitor-workflow-research.md) 和 [产品路线图](../plans/roadmap.md)，定义单管理员在响应式 Web/PWA 中完成规则约束自动整理闭环时的信息架构与交互基线。

本文负责回答：

1. 管理员进入 Web 后先看到什么，以及一级入口如何组织。
2. 全部任务、人工介入、失败与恢复如何在同一入口中表达。
3. 收件目录、资源库、规则、连接设置和媒体结果如何分工并互相跳转。
4. 桌面与移动浏览器宽度如何保持相同任务语义。
5. 中保真原型必须覆盖哪些状态、流程和验收场景。

本文不定义 API、事件、数据库枚举、领域对象持久化方式、Vue 组件结构或具体断点数值。这些事项分别交给 M1.6 和后续实现设计。

## 2. 范围与非目标

### 2.1 范围

- 单管理员首次配置与日常运行概览。
- 专用收件目录、MediaFlow 资源库、通用视频整理目标、整理规则和 TMDB 的配置入口，以及独立的 Jellyfin 连接设置。
- 发现、识别或确认、计划、文件操作、NFO 和本地完成的任务阶段表达。
- 待确认、冲突、失败、部分成功、中断恢复与重复发现的人工处理。
- 电影、剧集和受限通用视频的媒体列表与本地结果详情。
- 桌面、中等和移动浏览器宽度下的响应式 Web 交互。
- Loading、Empty、Error、Offline、Conflict 和 Partial Success 等必要状态。

### 2.2 非目标

- 不初始化或实现 `apps/web`、Core、数据库、API 或连接器。
- 不设计家庭成员账号、媒体消费首页、角色权限或多用户协作。
- 不提供内置播放、转码、播放进度或字幕能力。
- 不出现下载器、Emby、Plex、模型、外部通知、Bot、插件市场或工作流编辑器入口。
- 不把原型数据、页面或组件视为生产实现，也不让正式代码依赖 `labs/web-prototype/`。

## 3. 已确认的设计决定

1. 管理员完成首次配置后，默认进入以系统运行状态为中心的“概览”，而不是待处理列表或媒体墙。
2. 不设置独立一级“收件箱”。待确认、冲突、失败和部分成功全部由“任务”的“待处理”视图承载。
3. 一级信息架构采用平衡型结构：概览、任务、媒体、资源库、设置。
4. 正式交互对象是同一个响应式 Web/PWA；所谓桌面与移动只表示浏览器宽度变化，不表示原生客户端。
5. 视觉基线采用浅色管理型界面，优先保证任务、路径、规则、错误和恢复动作的可读性。
6. 媒体页展示已经建立正式媒体记录的结果；低置信度和未确认项目不得提前进入媒体列表。
7. Jellyfin 只在概览和设置中显示独立健康状态，并提供打开已配置服务首页的全局入口；不与 MediaFlow 资源库、任务或媒体项目关联。
8. 通用视频使用可复用整理目标和确定性规则完成名称格式化、相似内容聚合和文件夹归类；模糊相似或分组歧义必须在任务中暂停确认。

领域语言中的“收件箱”仍表示需要人工处理项目的工作入口，但 MVP Web 不为其设置独立一级导航；任务中心的“待处理”视图承担该职责。它与文件系统中的“专用收件目录”保持明确区分。

## 4. 全局信息架构

### 4.1 一级导航

```text
MediaFlow
├─ 概览        系统状态、处理阶段、待处理数量、近期结果和服务健康
├─ 任务        待处理、运行中、全部和已完成任务及其恢复动作
├─ 媒体        已建立正式媒体记录的电影、剧集和受限通用视频
├─ 资源库      收件目录、媒体资源库、通用视频整理目标和本地规则
└─ 设置        TMDB、Jellyfin、管理员会话、系统状态和诊断
```

“任务”的导航角标只统计需要管理员介入的项目，不统计全部运行任务。一级入口之间通过带上下文的链接跳转，不在多个页面复制同一列表或状态正文。

### 4.2 页面职责

| 页面 | 核心问题 | 不承担的职责 |
| --- | --- | --- |
| 概览 | 系统正在做什么、卡在哪里、核心服务和独立连接是否正常 | 不作为完整任务列表或统计报表中心 |
| 任务 | 某项处理处于什么阶段、已经发生什么、下一步如何恢复 | 不作为媒体浏览或连接器配置入口 |
| 媒体 | 已经形成哪些正式媒体记录及其本地文件与 NFO 结果 | 不展示未确认项目、不承担播放或媒体服务器关联 |
| 资源库 | 文件从哪里来、整理到哪里、按什么规则处理 | 不保存连接器凭据或全局健康诊断 |
| 设置 | 外部服务和系统本身能否正常工作 | 不决定资源库、任务或媒体项目如何关联外部服务 |

## 5. 响应式 Web 框架

### 5.1 宽屏 Web

宽屏浏览器使用固定文字侧栏和主内容区。概览可使用双列布局；任务列表与详情可并排展示。

```text
┌──────────────┬──────────────────────────────────────────┐
│ MediaFlow    │ 页面标题                      系统状态 ●  │
│ ● 概览       ├──────────────────────────────────────────┤
│   任务  [7]  │                                          │
│   媒体       │                 主内容                   │
│   资源库     │                                          │
│   设置       │                                          │
└──────────────┴──────────────────────────────────────────┘
```

### 5.2 中等宽度 Web

中等宽度将侧栏收起为图标导航，主内容改为单列或紧凑双列。页面职责和路由不变。

### 5.3 移动宽度 Web

移动宽度使用“概览、任务、媒体、更多”底部导航；“更多”包含资源库和设置。列表进入完整详情页，不保留左右分栏；返回时保持筛选条件和滚动位置。

```text
┌───────────────────────┐
│ 页面标题      系统 ●  │
│                       │
│     单列主内容        │
│                       │
├───────────────────────┤
│ 概览 │ 任务7 │ 媒体 │ 更多 │
└───────────────────────┘
```

三种宽度共享页面、路由、状态含义和恢复动作，只改变导航呈现和内容排列。

## 6. 运行概览

概览按以下顺序回答管理员的日常问题：

1. Core、专用收件目录和 TMDB 是否可用；可选的 Jellyfin 独立连接是否健康。
2. 当前有多少任务处于发现、识别或确认、计划、文件操作、NFO 和完成阶段。
3. 有多少待确认、冲突、失败或部分成功需要处理。
4. 最近产生了哪些成功或部分成功结果。

```text
处理阶段
[发现 2] → [识别 3] → [计划 1] → [文件操作 4] → [NFO 1] → [完成 8]

需要处理                         近期结果
待确认 3  冲突 2                 成功 8
失败 1    部分成功 1             部分成功 1

服务状态
收件目录 ●  TMDB ●  Jellyfin ◐ [打开首页]
```

每个数量和状态都必须跳转到对应页面与筛选结果。Jellyfin 健康卡片不参与任务计数，只能进入设置或打开已配置首页。概览不放置缺少下一步动作的装饰性统计图表。

## 7. 任务中心

### 7.1 列表与筛选

任务中心提供“待处理、运行中、全部、已完成”四个稳定视图，并支持按阶段、状态、资源库和文件或任务关键字筛选。从概览跳转时保留筛选上下文。

```text
[待处理 7] [运行中 12] [全部] [已完成]
阶段 ▼  状态 ▼  资源库 ▼  搜索文件或任务
```

### 7.2 任务详情

每个任务详情必须显示：

- 来源、授权边界、当前阶段和阶段时间线。
- 实际使用的识别依据、规则和整理计划。
- 已经产生的文件或本地结果，以及尚未执行的动作。
- 失败、暂停或部分成功的具体原因。
- 当前安全且可执行的下一步。

### 7.3 恢复动作

| 状态 | 展示重点 | 恢复动作 |
| --- | --- | --- |
| 待确认 | 候选、置信度、依据、原文件未改变 | 选择候选、修正信息或选择通用视频，然后重新计算计划 |
| 冲突 | 来源、目标、规则缺口或已存在文件 | 修正规则或目标，然后重新计算计划 |
| 失败 | 失败阶段、已产生结果、未执行动作 | 从安全检查点重试 |
| 部分成功 | 已完成与未完成的本地步骤，例如文件操作成功但 NFO 写入失败 | 保留文件结果，只重试未完成的本地步骤 |

重试不得重复执行已经安全完成的文件整理。任何界面都不得把硬链接失败静默改为复制或移动，也不得提供绕过授权路径的继续按钮。

Jellyfin 未配置或不可用只改变独立健康状态，不得创建任务阶段、待同步项目、下游重试动作或 Jellyfin 导致的部分成功。

### 7.4 通用视频确认

影视识别失败后，任务详情可以展示可复用的通用视频整理目标、目标根目录、固定文件操作、名称格式、分组依据、文件夹归类和简单 NFO 策略。来源目录、规范化名称、连续编号和显式规则等确定性依据可以直接形成计划；模糊相似或分组歧义必须暂停。

管理员确认分组时可以把结果保存为显式规则。保存后系统重新计算计划，并在文件修改前再次展示来源、目标、名称和分组结果；该路径不伪造 TMDB 身份，也不扩展为完整课程或通用内容领域模型。

### 7.5 任务流转

```text
概览状态
  → 带筛选进入任务中心
  → 查看依据、计划和实际影响
  → 确认、修正或重试
  → 原任务恢复并继续
  → 成功结果进入媒体详情
```

## 8. 资源库与设置

### 8.1 资源库

资源库页面包含三类明确对象：专用收件目录、电影或剧集 MediaFlow 资源库，以及可复用的通用视频整理目标。

```text
资源库
├─ 收件目录
│  ├─ 授权路径
│  ├─ 监听与对账状态
│  └─ 最近发现任务
├─ 电影资源库
│  ├─ 目标目录与文件操作
│  ├─ 命名与 NFO 规则
│  └─ 自动执行条件
├─ 剧集资源库
│  └─ 同样结构，并表达季、集和版本规则
└─ 通用视频整理目标
   ├─ 授权目标根目录与固定文件操作
   ├─ 名称格式和简单 NFO 策略
   ├─ 确定性相似内容聚合依据
   └─ 文件夹归类与歧义确认规则
```

资源库详情提供相关任务和已整理媒体的链接，但不复制完整任务列表或媒体详情。动漫复用剧集规则，不出现独立动漫配置域。资源页面不显示 Jellyfin 媒体库，也不判断目标目录是否被 Jellyfin 收录。

### 8.2 设置

```text
设置
├─ 元数据
│  └─ TMDB：凭据、连接测试和健康状态
├─ 媒体服务器
│  └─ Jellyfin：地址、凭据、连接测试、健康状态和打开首页
└─ 系统
   ├─ 管理员账号与会话
   ├─ Core 与存储状态
   └─ 诊断信息
```

Jellyfin 配置与健康状态属于设置，并与资源库、任务和媒体项目完全独立。MVP 不展示媒体库映射、扫描、可见性验证、媒体级跳转，也不展示未交付能力的禁用菜单或“即将推出”占位入口。

### 8.3 首次配置

```text
配置 TMDB
  → 配置专用收件目录
  → 创建电影、剧集资源库和可选通用视频整理目标
  → 选择文件操作、命名、分组和 NFO 规则
  → 检查路径权限、元数据连接和配置摘要
  → 进入运行概览
```

首次配置只验证配置、权限和 TMDB 连接，不移动或修改媒体文件。Jellyfin 不属于首次配置必需项，管理员可以稍后在设置中单独配置、测试或打开首页。

## 9. 媒体列表与详情

### 9.1 进入条件与分类

媒体页只展示已经建立正式媒体记录的内容。低置信度、识别失败和未确认项目继续留在任务中心。人工确认并整理完成的课程或自制视频可以进入“通用视频”，但不得伪造 TMDB 身份。

媒体分类为全部、电影、剧集和通用视频；动漫复用剧集分类。媒体状态只表达本地整理、NFO 和记录结果，不显示待同步或 Jellyfin 可见性。

### 9.2 媒体详情

媒体详情展示：

- 标题、年份、类型、海报和展示元数据。
- 识别依据与字段来源。
- 媒体版本、实际文件、来源路径与当前路径。
- 文件操作方式、NFO 状态与实际更新结果。
- 本地整理结果、相关任务和整理计划。

剧集详情使用“剧集 → 季 → 单集 → 版本 → 文件”层级。移动宽度将海报、摘要、状态和操作纵向排列。

媒体详情不得提供 Jellyfin 媒体库状态、扫描状态、可见性或媒体级外部跳转。

## 10. 页面状态与错误恢复

| 状态 | 统一界面行为 |
| --- | --- |
| Loading | 保留导航与页面骨架，避免内容整体跳动 |
| Empty | 说明为何为空，并提供一个明确下一步 |
| Error | 显示失败对象、阶段、原因和重试入口，不以空数据代替错误 |
| Offline | 全局提示 Core 不可达，禁用需要服务端确认的操作 |
| Conflict | 展示来源、目标、规则和冲突点，默认不执行文件操作 |
| Partial Success | 分别列出已完成、未完成和可重试部分 |
| Success | 明确展示文件操作、NFO 和媒体记录均已完成 |

状态信息不得只使用颜色表达。全局错误不能覆盖任务自身已经保存的结果；Jellyfin 等独立连接失败不得出现在任务状态中，也不得让已经安全完成的本地整理看起来被回滚。

## 11. 设计系统基础

### 11.1 视觉方向

- 采用浅灰页面背景、白色内容容器和深灰主文字的浅色管理型界面。
- 蓝色表示主要操作；绿色表示成功；琥珀色表示待处理或部分成功；红色表示失败或冲突。
- 所有状态同时使用图标和文字，不依赖颜色单独传达含义。
- 文件路径、规则片段和技术标识使用等宽字体，并允许安全换行或复制。
- 信息密度服务于管理任务，不使用大面积装饰图片挤压阶段、错误和恢复信息。

### 11.2 交互原则

- 每个状态只突出一个主要恢复动作，次要动作保持可见但不竞争注意力。
- 任何文件影响都先展示来源、目标、操作类型和冲突结果。
- 返回列表时保留筛选、排序和滚动位置。
- 桌面和移动宽度使用相同术语、状态和动作名称。
- 键盘焦点、对比度、触控区域和表单错误提示必须可辨识。

## 12. 中保真原型范围

中保真可交互原型位于 `labs/web-prototype/`，只使用模拟数据，不连接真实 Core、文件系统、TMDB 或 Jellyfin。`apps/web` 在 M1.4 保持未初始化。

原型至少覆盖以下流程：

| 原型流程 | 演示内容 |
| --- | --- |
| P1 首次配置 | TMDB、收件目录、资源库、通用视频整理目标、规则与配置摘要；Jellyfin 作为可选独立设置 |
| P2 自动成功 | 电影或剧集从发现到本地整理与 NFO 完成，并进入媒体详情 |
| P3 人工确认 | 低置信度候选、人工修正、通用视频分组预览、歧义确认、保存显式规则与重新计算计划 |
| P4 安全暂停 | 目标冲突、规则未覆盖、硬链接条件失败、NFO 保护和越权路径 |
| P5 本地部分成功与连接隔离 | 文件操作成功但 NFO 写入失败时只重试 NFO；Jellyfin 不可用只显示独立健康状态 |
| P6 恢复 | Core 中断后恢复、重复发现复用原任务 |
| P7 结果查看 | 媒体详情、文件与版本、本地 NFO 结果和相关任务 |

原型覆盖宽屏和移动浏览器宽度，并为适用页面提供 Loading、Empty、Error、Offline、Conflict 和 Partial Success 状态。原型只演示交互和状态，不成为第二套需求来源。
