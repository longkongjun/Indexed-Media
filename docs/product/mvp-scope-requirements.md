## 2. MVP 范围

### 2.1 用户与闭环

- MVP 只提供一个管理员身份，不提供家庭成员账号、角色配置或企业级权限模型。
- 管理员在 MediaFlow Web 中配置专用收件目录、资源库、整理规则和 TMDB，处理异常并查看结果；Jellyfin 连接是与整理任务解耦的可选设置。
- 家庭成员直接使用 Jellyfin 浏览和播放，不属于 MVP 的 MediaFlow 内验收对象。
- MVP 成功闭环是：发现收件文件、识别或暂停确认、生成计划、按授权规则安全执行文件操作、受控写入 NFO，并让管理员能够查看本地结果、理解异常和安全恢复。

### 2.2 文件入口与内容类型

- 首个且唯一的正式文件入口是管理员显式配置的专用收件目录。MediaFlow 持续发现文件、周期性对账，并用持久任务记录处理状态。
- MVP 不提供独立的已有媒体目录扫描或导入入口；已有文件需要由用户放入专用收件目录。
- 正式支持电影和剧集。动漫暂时复用剧集规则，不建设动漫专属领域模型。
- 影视识别失败后，管理员可以人工选择按通用视频进行受限整理，用于课程、自制视频等内容；通用视频不是与电影、剧集并列的完整类型系统。
- 管理员可以配置可复用的通用视频整理目标，包括授权目标根目录、固定文件操作、名称格式、文件夹归类和简单 NFO 策略。
- 来源目录、规范化名称、连续编号和显式规则等确定性依据可以自动格式化名称、聚合相似内容并按文件夹归类；模糊相似或分组歧义必须暂停确认，确认结果可以保存为后续复用的显式规则。

### 2.3 识别与待确认

- MVP 使用文件名、目录层级、媒体技术信息、已有 NFO、TMDB 和人工修正作为识别依据。
- MVP 不调用本地或远程模型。一个内置本地模型适配器属于 M4，不是 MVP 可用能力。
- 低置信度或候选冲突时，MediaFlow 保留原文件并建立隔离的待确认媒体记录，记录候选、置信度和依据。
- 待确认记录不写 NFO、不执行文件整理，也不进入正式媒体视图。
- 人工修正保存为后续识别依据，并可以重新生成整理计划。

### 2.4 规则约束自动整理

- 管理员可以一次性授权目录，并为资源库配置可复用整理规则。
- 每次整理前都必须生成并保存包含来源、目标、命名和操作类型的整理计划。
- 命中授权目录、显式规则和低风险条件的计划可以自动执行，不要求逐次点击确认；计划和执行结果仍必须可查看、可审计。
- 冲突、越权路径、覆盖目标、规则未覆盖或前置条件不满足时必须暂停，等待管理员确认或修正。

### 2.5 文件操作与 NFO

- 每个资源库固定选择移动、复制或硬链接，自动任务不得临时改用另一种操作。
- 硬链接只允许在同一文件系统中使用；条件不满足时任务暂停，不得静默降级为复制或移动。
- 默认不覆盖或删除已有文件。所有文件变化必须通过路径授权、安全检查、持久记录和支持范围内的恢复机制。
- 扫描和识别优先复用已有 NFO。身份确认且整理成功后，MediaFlow 可以按资源库配置生成缺失 NFO。
- 已有 NFO 默认保留，只更新规则明确允许的字段；低置信度待确认记录不写 NFO。

### 2.6 Jellyfin 独立连接与管理员 Web

- Jellyfin 在 MVP 中只保留服务地址、凭据、连接测试、健康状态和打开服务首页的全局入口。
- MediaFlow 不建立自身资源库与 Jellyfin 媒体库的关联，不请求 Jellyfin 扫描，也不验证媒体是否可见；目标目录是否被 Jellyfin 收录完全由用户在 Jellyfin 中配置。
- Jellyfin 未配置或不可用不得阻塞、降级或改变本地整理任务结果，也不得产生待同步、下游重试或 Jellyfin 导致的部分成功状态。
- 管理员 Web 必须展示任务阶段、整理计划、识别依据、等待确认、冲突、失败、部分成功和最终结果。
- MVP 的等待确认、失败和结果只在 MediaFlow Web 内处理，不发送外部通知，也不接受 Bot 指令。

## 3. 明确非目标

- 不连接 qBittorrent、Transmission 或其他下载器，不接收 RSS、Webhook 或下载完成事件。
- 不提供独立已有媒体目录扫描、逐文件手动添加或多个正式文件入口。
- 不完整支持课程、自制视频等通用媒体类型，不建设照片、图书或漫画能力。
- 不调用本地模型、远程模型或云端 AI 服务。
- 不发布外部智能 provider 协议、稳定第三方 SDK、通用插件运行时或可视化工作流编辑器。
- 不支持 Emby、Plex 或多个媒体服务器同时同步。
- 不提供外部 Webhook、飞书、企微、Slack 等通知渠道，也不提供入站 Bot 指令。
- 不提供家庭成员账号、自定义角色、企业级 RBAC、移动端或 TV 客户端。
- 不自研播放器、转码、字幕渲染、播放进度主数据、站点聚合、Cookie 托管或资源搜索。
- 不在 M1.3 定义页面结构、组件样式、API、事件、数据库或具体实现技术。

## 5. 验收场景

### `MVP-AC-001` 电影自动整理闭环

- **Given** 管理员已经配置专用收件目录、电影资源库、明确整理规则、文件操作方式和 TMDB。
- **When** 一个可由本地依据和 TMDB 高置信度识别、且命中授权规则的电影文件进入收件目录。
- **Then** MediaFlow 持久化任务和整理计划，自动执行已配置的文件操作并按策略补齐 NFO；管理员能在 Web 中查看依据、计划、实际变化和本地最终结果。

### `MVP-AC-002` 剧集与单集关系

- **Given** 管理员已经配置剧集资源库和命名规则。
- **When** 一个包含季号、集号和版本信息的剧集文件进入收件目录。
- **Then** MediaFlow 建立剧集、季度、单集、媒体版本和文件之间的关系，按规则完成文件整理和受控 NFO 写入，并展示本地结果。

### `MVP-AC-003` 低置信度隔离与修正

- **Given** 收件文件存在多个可信候选，当前结果不满足自动执行条件。
- **When** 识别阶段完成。
- **Then** 原文件保持不变，系统建立包含候选、置信度和依据的待确认记录，不写 NFO、不整理；管理员修正后，系统保存反馈并重新生成计划。

### `MVP-AC-004` 通用视频受限整理

- **Given** 管理员已经配置通用视频整理目标，一个课程或自制视频无法通过影视信息源可靠识别。
- **When** 管理员选择按通用视频整理，系统依据来源目录、规范化名称、连续编号和显式规则计算名称与文件夹分组。
- **Then** 确定性结果可以生成可审查的整理计划；存在模糊相似或分组歧义时必须暂停确认，管理员可以保存明确规则并重新计算计划。系统建立最小通用视频记录和简单 NFO，不伪造 TMDB 身份，也不要求完整通用媒体类型能力。

### `MVP-AC-005` 规则未覆盖或文件冲突

- **Given** 文件身份已经确认，但目标路径已存在文件，或当前计划没有命中显式规则。
- **When** 系统评估整理计划。
- **Then** 任务暂停并展示冲突或规则缺口，默认不覆盖、不删除、不执行文件操作；管理员修正规则或目标后可以重新计算计划。

### `MVP-AC-006` 硬链接前置条件失败

- **Given** 资源库配置为硬链接，但来源和目标不在同一文件系统。
- **When** 系统验证文件操作前置条件。
- **Then** 任务暂停并说明硬链接不可用，不得静默降级为复制或移动，也不得产生部分目标文件。

### `MVP-AC-007` 已有 NFO 保护

- **Given** 文件旁已经存在包含用户自定义字段的 NFO。
- **When** 身份确认并完成文件整理。
- **Then** 系统保留已有 NFO，只更新资源库策略允许的字段，并在任务结果中记录实际更新内容。

### `MVP-AC-008` Jellyfin 与本地任务解耦

- **Given** 管理员已配置 Jellyfin 连接但服务当前不可访问，同时存在满足授权和规则条件的本地整理任务。
- **When** MediaFlow 执行该任务并刷新独立的 Jellyfin 健康状态。
- **Then** 文件操作和 NFO 均成功时任务正常完成；Jellyfin 只显示独立健康警告，不产生待同步、下游重试或部分成功状态，也不建立任何媒体库关联。

### `MVP-AC-009` 重复发现与中断恢复

- **Given** 一个文件已经建立任务，Core 在处理过程中重启，之后收件目录再次发现同一文件。
- **When** 任务恢复和目录对账执行。
- **Then** 系统恢复或继续原任务，不建立导致重复文件操作的新任务，并向管理员显示恢复后的阶段和已有结果。

### `MVP-AC-010` 越过授权目录

- **Given** 规则或异常文件名计算出的目标路径超出管理员授权的资源库根目录。
- **When** 系统执行路径安全检查。
- **Then** 任务在任何文件修改前失败或暂停，记录越权原因和计划目标，不创建、覆盖、移动或删除文件。
