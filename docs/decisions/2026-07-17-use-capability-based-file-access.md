# 使用能力目录限制文件访问

> 日期：2026-07-17
> 状态：accepted

## 背景

MediaFlow 会根据不可信文件名、NFO、外部元数据和管理员规则计算目标路径。字符串前缀、规范化后的文本比较和容器内 root 权限都不足以防止符号链接、挂载变化、`..` 和检查后使用竞态导致的越权访问。

## 决定

文件访问使用两层能力边界：部署者只挂载 Core 可以访问的根目录，管理员只能在这些根目录内配置收件目录和唯一目标根目录。Core 从已经验证或打开的能力目录执行相对路径操作，不通过任意绝对路径访问文件。

计划和执行阶段都要核对来源身份、目标父目录、挂载能力、符号链接和冲突。目标创建默认不覆盖；无法证明路径仍在授权边界内时暂停。容器不使用特权模式，也不挂载整个 NAS 根目录。

## 后果

正面后果：

- 文件安全边界不依赖易出错的字符串前缀判断。
- Web 管理员无法扩大部署者授予容器的文件权限。
- 路径逃逸和竞态可以在统一平台端口与真实文件系统测试中验证。

代价与限制：

- 部署者必须预先挂载可能使用的目录，并配置正确 UID/GID。
- NAS、Linux 和网络挂载的能力语义需要逐类验证。
- 符号链接或挂载状态不明确时会安全暂停，可能需要管理员调整目录布局。

## 未采用方案

- 只比较规范化路径字符串：无法可靠覆盖符号链接和检查后使用竞态。
- 容器挂载整个 NAS 后依赖应用配置限制：权限过大，配置错误的影响不可接受。
- 为每次操作使用特权辅助进程：扩大攻击面和部署复杂度，不符合 MVP。
