# MediaFlow 归档策略与来源记录

## 强制规则

`archive/**` 永久只读，只能作为历史参考。只有当活动任务包写明具体归档路径和读取原因时，执行者才可以读取该路径。

禁止对归档执行以下操作：

- 修改、删除、格式化或重命名任何文件或目录。
- 为旧文档补链接、修正文案或更新元数据。
- 将归档加入构建、测试、workspace、依赖解析或默认搜索。
- 从归档直接导入代码，或把完整旧目录恢复到活跃区。

需要复用旧行为时，必须依据当前契约在活跃区重新实现，并先增加能够描述该行为的新测试。归档只提供参考，不是可维护实现。

## 迁移前本地载荷基线

归档迁移前已存在以下三个本地载荷。它们受 `.gitignore` 约束，不进入 Git，也不得读取、输出或提交内容：

- `archive/2026-07-10-pre-rebuild/source/mediaflow-client/local.properties`
- `archive/2026-07-10-pre-rebuild/source/server/config.toml`
- `archive/2026-07-10-pre-rebuild/source/server/data/mediaflow.db`

公开仓库不分发重建前的内部工程归档。需要保留的稳定产品事实必须进入当前产品、架构、决策或契约目录，不能依赖本地历史归档才能理解。

未来重新评估归档检查时，应继续遵守以下候选规则：干净克隆可以完全不存在这三个文件；若其中任一文件存在，则三者必须全部存在且 SHA-256 与基线完全匹配。重新启用前不得把该候选规则描述为已生效门禁。
