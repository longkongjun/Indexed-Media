## 2. 已确认架构决定

MVP 采用以下基线：

1. Core 是领域主导的模块化单体；`tasks` 协调流程，但不拥有识别、规则或文件安全业务规则。
2. 一个 MediaFlow 资源库或通用视频整理目标只对应一个目标根目录；多个物理根目录使用多个目标对象表达。
3. 通用视频使用持久化的最小分组和成员对象，不引入课程、讲师或章节领域。
4. 每个发现文件对应一个持续推进的处理任务；扫描批次只聚合和关联文件任务。
5. 文件系统变化使用持久操作日志、幂等步骤和实际结果核对，不虚构跨文件系统事务。
6. 配置按安全不变量、目标基础配置、显式规则和当前任务决定分层，并冻结为不可变计划快照。
7. MVP 建立最小 `Account + Session` 与稳定能力检查，不提前实现多用户或可配置 RBAC。
8. 连接器按能力类型定义编译期端口和内置适配器，不提供动态插件运行时。
9. 参考容量为 10 万文件记录、5 万媒体项目和最多 20 个并行文件任务。

长期选择的背景和后果另见：

- [持久任务与文件操作日志](../decisions/2026-07-17-use-durable-task-and-file-journals.md)
- [能力目录文件访问](../decisions/2026-07-17-use-capability-based-file-access.md)
- [类型化内置连接器能力](../decisions/2026-07-17-use-typed-built-in-connector-capabilities.md)

## 3. 系统上下文与信任边界

```text
管理员浏览器
    │ HTTPS / 同源 Cookie
    ▼
MediaFlow Core + Web
    ├─ SQLite /config
    ├─ ffprobe 子进程
    ├─ 部署授权目录
    ├─ TMDB
    └─ Jellyfin（独立健康与首页）
```

Core 只信任已经认证的管理员会话和由部署者提供的能力目录。文件名、目录层级、NFO、媒体技术信息、外部 HTTP 响应和浏览器输入均视为不可信输入，必须经过大小、格式、路径和权限检查。

部署者的容器挂载是第一层授权；管理员在 Web 中选择的收件目录和目标根目录必须是这些挂载的子目录，形成第二层授权。应用不能通过 Web 请求扩大容器自身的挂载能力。

## 4. 领域模型

### 4.1 位置、入口与整理目标

| 对象 | 职责 | 关键不变量 |
| --- | --- | --- |
| `DeploymentRoot` | 部署者挂载给 Core 的能力目录 | 只在启动配置中声明，Web 不可扩大 |
| `InboxDirectory` | 专用收件目录及监听、对账和健康状态 | 必须位于可用的部署根内；只表示文件入口 |
| `Library` | 电影或剧集的逻辑资源库和唯一目标根目录 | 一个资源库一个目标根；动漫复用剧集类型 |
| `GenericVideoTarget` | 受限通用视频的唯一目标根目录 | 不升级为完整通用内容资源库 |
| `OrganizationProfile` | 目标的固定文件操作、命名、NFO 和自动执行基础配置 | 与一个目标一对一；有独立版本 |

MVP 可以配置多个 `InboxDirectory`、`Library` 或 `GenericVideoTarget`，但每个对象都只能有一个规范化根目录。收件目录与目标目录、两个目标目录之间不得出现相同或相互包含的规范化路径，避免同一文件被两个流程同时声明所有权。

### 4.2 发现、识别与人工介入

| 对象 | 职责 |
| --- | --- |
| `DiscoveryBatch` | 一次目录枚举或周期对账的批次、游标、计数和结果摘要 |
| `DiscoveredFile` | 未确认身份的文件快照、来源目录、相对路径、大小、时间、文件系统标识和按需指纹 |
| `ProcessingTask` | 一个发现文件的一条持久处理时间线 |
| `IdentificationAttempt` | 一次识别使用的依据、候选、置信度、规则版本和结果 |
| `ReviewCase` | 待确认、候选冲突、通用视频分组歧义或规则缺口 |
| `TaskDecision` | 管理员对当前任务的候选、分组、规则或恢复决定 |

`DiscoveredFile` 不等于正式媒体记录。低置信度时只保存发现快照、识别尝试和 `ReviewCase`，不创建正式 `MediaItem`、不写 NFO、也不执行文件整理。

重复发现首先使用稳定来源目录 ID、规范化相对路径、大小、修改时间和可用的文件系统标识匹配。存在重命名、时间精度不足或身份冲突时再计算 BLAKE3 快速指纹；完整哈希只在快速证据仍不足或安全核对需要时计算。

### 4.3 计划与文件影响

| 对象 | 职责 | 关键不变量 |
| --- | --- | --- |
| `EffectiveConfigSnapshot` | 每个生效字段的值、来源、来源版本和求值时间 | 生成后不可变 |
| `OrganizationPlan` | 来源、目标、命名、分组、操作和 NFO 的版本化预演 | 任何文件变化前必须持久化 |
| `PlannedFileOperation` | 单个复制、移动、硬链接或 NFO 步骤及前置条件 | 具有稳定操作 ID |
| `FileOperationJournal` | 操作准备、执行、核对、补偿和人工处理状态 | 已验证步骤不得重复执行 |
| `LocalResult` | 实际文件变化、NFO 结果、未完成项和恢复动作 | 只描述 MediaFlow 本地结果 |

重新计算计划必须创建新版本并保留旧版本。管理员确认计划、保存显式规则或重试未完成步骤时，都必须记录使用的计划版本。

### 4.4 正式媒体记录

```text
电影
└─ Movie → MediaVersion → FileAsset

剧集
└─ Series → Season → Episode → MediaVersion → FileAsset

通用视频
└─ GenericVideoGroup
   ├─ GenericVideoItem 01 → MediaVersion → FileAsset
   └─ GenericVideoItem 02 → MediaVersion → FileAsset
```

| 对象 | 职责 |
| --- | --- |
| `MediaItem` | 用户理解的逻辑媒体项目；具体种类为电影、剧集、季、单集、通用视频分组或成员 |
| `MediaVersion` | 同一媒体项目的具体版本，例如 1080p、4K 或剪辑版 |
| `FileAsset` | 已与媒体版本关联的实际文件、当前位置、大小、指纹和技术参数 |
| `MetadataValue` | 单个展示字段的值、来源、来源标识、优先级和人工覆盖信息 |
| `ArtworkRef` | 海报、背景图等展示资源的来源和本地缓存引用 |

`GenericVideoGroup` 只保存名称、确定性分组依据、规则来源和成员顺序；`GenericVideoItem` 只保存展示名称、序号、文件关系和简单元数据。二者不得增加课程、讲师、章节、学习进度或伪造的 TMDB 身份。

文件操作成功后，即使 NFO 或最终记录步骤失败，也必须保存可追踪的本地结果。NFO 失败时可以建立带有明确 NFO 状态的媒体记录；修复任务只重试 NFO 或未完成的记录步骤，不重复文件操作。

### 4.5 连接、身份与审计

| 对象 | 职责 |
| --- | --- |
| `IntegrationConfig` | 连接类型、非敏感配置和加密凭据引用 |
| `IntegrationCapability` | 当前适配器明确支持的能力集合 |
| `IntegrationHealth` | 最后检查时间、延迟、状态和脱敏错误 |
| `Account` | MVP 唯一管理员账号 |
| `Session` | 可吊销的管理员 Web 会话 |
| `CapabilityGrant` | 业务用例使用的稳定能力标识；MVP 全部授予管理员 |
| `AuditEvent` | 登录、配置、规则、人工决定、文件影响和恢复操作的审计记录 |

`IntegrationConfig`、`IntegrationHealth`、`Library`、`ProcessingTask` 和 `MediaItem` 之间不得建立 Jellyfin 媒体库或媒体项目映射。

### 4.6 关系总览

```text
InboxDirectory
    └─ DiscoveryBatch
        └─ DiscoveredFile ── ProcessingTask
                                  ├─ IdentificationAttempt
                                  ├─ ReviewCase / TaskDecision
                                  ├─ OrganizationPlan
                                  └─ FileOperationJournal
                                             │
                                      已确认本地结果
                                             ▼
Library / GenericVideoTarget ── MediaItem ── MediaVersion ── FileAsset
```

大集合不放在单一聚合内：`Library` 不内嵌全部媒体，`ProcessingTask` 不内嵌全部事件，`MediaItem` 不内嵌文件内容。聚合之间只保存稳定 ID，并通过应用用例协作。

## 5. 模块边界

| 模块 | 拥有的主要对象与行为 | 不允许承担 |
| --- | --- | --- |
| `catalog` | `Library`、`GenericVideoTarget`、媒体层级、版本、文件关联、元数据和媒体查询 | 扫描目录、执行文件操作、调用 Jellyfin |
| `discovery` | 收件目录、扫描批次、文件观察、周期对账和发现去重 | 判断媒体身份、生成目标路径 |
| `identification` | 本地解析、NFO 读取、候选、置信度、人工识别反馈和 `ReviewCase` | 修改媒体文件、决定自动执行权限 |
| `organization` | 目标配置、规则、最终配置、计划、文件安全、journal、NFO 和支持范围内的恢复 | 保存管理员会话、管理连接器凭据 |
| `tasks` | 文件任务、阶段、状态、租约、检查点、重试、取消和流程协调 | 内嵌识别、命名、路径或 NFO 业务规则 |
| `connectors` | 类型化能力端口、内置适配器、连接配置、健康和调用策略 | 直接写目录主数据或改变任务成功状态 |
| `identity` | 账号、密码凭据、会话、能力检查和吊销 | 预建家庭成员或可配置 RBAC |
| `admin` | 系统配置、审计、备份、迁移、诊断和健康聚合 | 执行媒体领域规则 |
| `platform` | SQLite、能力目录、时钟、加密、HTTP、进程和观测实现 | 包含业务决策 |

模块拥有自己的 repository 和表。一个模块不得直接读取另一个模块的 repository 或表；跨模块查询使用应用接口或专用只读投影。`shared` 只保存稳定 ID、时间、分页和错误信封等真正通用类型，不能成为跨模块业务代码堆放区。

## 6. 流程协调与数据流

```text
1. discovery 保存 DiscoveredFile
2. tasks ensure ProcessingTask；重复发现复用原任务
3. identification 计算候选、依据和置信度
4. 不确定则创建 ReviewCase 并暂停
5. organization 求值配置并生成不可变计划
6. tasks 根据计划结论自动继续或安全暂停
7. organization 按 journal 执行文件操作和 NFO
8. catalog 根据已核对的本地结果建立或更新媒体记录
9. task + outbox 事件更新审计、SSE 和页面读模型
```

`tasks` 只保存流程状态、调用结果引用和下一步；它通过 `IdentificationService`、`OrganizationService`、`CatalogService` 等应用端口调用领域模块。领域模块返回可持久化的决定或结果，不把内部 repository 暴露给协调器。

扫描批次任务只保存目录枚举进度和文件任务关联。单文件失败不会让整个批次失败；批次结果分别统计新建、复用、跳过、失败和等待处理的文件任务。

## 7. 配置、规则与计划快照

配置使用以下固定优先级：

```text
安全不变量（不可覆盖）
        ↓
Library / GenericVideoTarget 基础配置
        ↓
命中的显式规则
        ↓
当前 TaskDecision
        ↓
EffectiveConfigSnapshot
        ↓
OrganizationPlan
```

安全不变量包括授权根目录、不覆盖、硬链接同文件系统、禁止静默降级、NFO 保护和已完成步骤不重复执行。任何配置、规则或人工决定都不能覆盖这些约束。

每个最终字段至少保存：

- `value`
- `source_type`
- `source_id`
- `source_version`
- `evaluated_at`

配置和规则使用版本号与乐观并发检查。计划生成后，配置变化不得静默改变正在处理的任务；管理员必须显式重新计算，系统创建新计划版本。通用视频歧义确认只有在管理员选择“保存为规则”时才创建可复用规则；一次性确认默认只属于当前任务。

## 8. 任务状态、租约与恢复

### 8.1 阶段与状态分离

用户可见阶段保持与交互基线一致：

```text
discovery → identification → planning → file-operation → nfo → completion
```

`completion` 内部可以包含建立媒体记录、写入最终结果和发布完成事件等检查点，但不增加新的一级 UI 阶段。

任务状态独立保存：

| 状态 | 含义 |
| --- | --- |
| `queued` | 已持久化，等待租约 |
| `running` | Worker 正在执行当前检查点 |
| `waiting-confirmation` | 等待候选、通用视频分组或其他人工决定 |
| `paused` | 因冲突、越权、覆盖、规则缺口或前置条件失败安全暂停 |
| `failed` | 当前任务不能继续，保存可恢复性和失败检查点 |
| `partial-success` | 已产生安全本地结果，但 NFO 或记录步骤尚未完成 |
| `completed` | 本地文件、NFO 策略和媒体记录均已形成最终结果 |
| `cancelled` | 在安全检查点接受取消；已完成步骤不会自动撤销 |

状态必须同时保存阶段、稳定原因码、已产生结果、尚未执行动作、可恢复性和建议动作。Jellyfin 健康永远不会成为任务阶段、状态或原因码。

### 8.2 租约与启动恢复

任务先写 SQLite，再由 Worker 获取带期限租约。Worker 定期续租；Core 重启后回收过期租约，但不会假定租约过期意味着文件步骤未发生。

```text
Core 启动
  → 回收过期任务租约
  → 查找未结束 journal
  → 核对检查点与实际文件状态
  → 已验证步骤直接跳过
  → 可以确定则继续或重试
  → 状态不明确则进入人工处理
```

任务命令、计划版本、操作步骤和 outbox 事件都使用稳定 ID。重试和至少一次事件交付必须由接收方按 ID 幂等处理。

## 9. 文件安全与操作日志

### 9.1 能力目录

文件访问必须从已经打开或验证的能力目录出发，不使用路径字符串前缀作为安全判断。每次计划和执行都要验证：

1. 来源和目标属于预期能力根目录。
2. 规范化路径不存在 `..`、非法绝对路径或跨根符号链接。
3. 现有父目录和挂载身份没有在计划后发生意外变化。
4. 来源文件身份与计划快照一致。
5. 目标不存在，或当前操作明确属于对同一操作的恢复核对。

MVP 不允许通过符号链接越过授权根目录；遇到无法可靠解析的链接或挂载变化时暂停。文件名、NFO 字段和外部元数据不能直接拼接为未校验路径。

### 9.2 Journal 状态

```text
prepared → executing → applied → verified
                         │
                         ├─ compensated
                         └─ manual-review
```

- `prepared`：计划版本、来源快照、目标、前置条件和操作 ID 已持久化。
- `executing`：Worker 已取得步骤租约，可能正在影响文件系统。
- `applied`：观察到预期文件影响，尚未完成最终核对。
- `verified`：目标身份、大小、指纹或 inode 等核对通过。
- `compensated`：只撤销了由同一操作创建且仍未被外部修改的结果。
- `manual-review`：实际状态无法安全自动判断。

### 9.3 操作语义

- **复制**：在目标目录写入唯一临时文件，流式计算校验，刷新落盘后使用不覆盖的同目录原子改名。恢复时先核对临时文件和最终目标。
- **同文件系统移动**：使用不覆盖原子改名并核对目标身份。
- **跨文件系统移动**：复制、校验、提交目标后才删除来源；任一步不确定都保留可追踪结果并暂停，不把失败伪装为完整移动。
- **硬链接**：先验证来源和目标位于同一文件系统，使用不覆盖创建并核对 inode 或等价文件身份；不满足时暂停，不降级。
- **NFO**：解析已有内容，只修改策略允许字段，写临时文件、刷新并原子替换；保存旧内容版本或可恢复副本及哈希。

默认不覆盖或删除已有目标。移动策略中删除已验证来源属于用户显式选择的移动语义，不扩大为通用删除能力。

### 9.4 支持范围内的恢复

- 复制和硬链接只删除由同一操作创建且身份仍匹配的目标。
- 移动只在原位置可用、目标未变化且反向操作安全时自动恢复，否则人工处理。
- NFO 只在当前文件仍匹配预期版本时恢复旧内容。
- 不对外部程序已经修改的文件做自动覆盖式回滚。

## 10. 持久化、事务与内部事件

MVP 使用一个 SQLite 数据库，启用 WAL、外键、显式短事务和需要时的 FTS5。数据库必须位于 SQLite 兼容的本地卷；不支持把 `/config` 数据库放在 SMB、NFS 或其他不保证所需锁语义的网络文件系统。

模块各自拥有表和迁移。单个模块内使用本地事务；跨模块流程使用幂等应用命令、任务检查点和 outbox，不建立跨文件系统或跨外部服务的大事务。

领域状态和对应 outbox 事件在同一 SQLite 事务中提交。后台分发器采用至少一次交付，消费者按事件 ID 去重。内部事件发布已经提交的事实，不替代 `tasks` 对主流程的显式协调。它用于：

- 更新概览、任务和媒体读模型。
- 生成审计与 SSE 增量。
- 触发不决定主任务下一阶段的附属处理。

内部事件不是公开契约。M1 不在 `contracts/events/` 创建代表已实现能力的事件；M2 根据真实纵向切片定义首个版本化事件。

迁移只向前执行，升级前先生成数据库和配置备份并校验可读性。备份恢复必须在干净实例中验证 Schema 版本、外键和关键计数后才允许切换。

## 11. REST、SSE 与页面读模型

所有正式客户端通过 `/api/v1` REST/JSON 和认证 SSE 与 Core 通信。OpenAPI 是 REST 契约唯一事实来源，但具体路径、DTO 和状态码只在 M2 实现型 change 中创建。

接口基线：

- 创建任务或产生副作用的可重放请求支持幂等键。
- 大列表使用服务端分页、稳定排序和游标；默认页大小由实现 change 定义并设上限。
- 错误包含稳定错误码、可操作说明和 `request_id`，不返回内部堆栈或密钥。
- 路径只向已认证管理员显示完成任务所需的信息；诊断和通用日志默认脱敏。
- 修改请求必须经过能力检查和 CSRF 防护。

SSE 使用单调递增事件 ID，支持 `Last-Event-ID` 恢复，交付语义为至少一次。客户端按事件 ID 去重，断线后先恢复事件，再在检测到缺口时刷新对应读模型。SSE 只传递任务、媒体、资源库和健康投影变化，不承担模块间事务。

页面读模型与 M1.4 对齐：概览、任务、媒体、资源库和设置分别拥有面向查询的投影。投影可以重建，不能成为任务、文件或权限的唯一主数据。

## 12. 身份、会话、密钥与审计

### 12.1 单管理员初始化

当数据库不存在账号时，Core 才允许管理员初始化。部署者必须通过环境变量、Docker secret 或权限为 `0600` 的本地引导文件提供一次性引导密钥；密钥不得出现在普通日志、URL 或未认证 API 响应中。管理员创建成功后立即使其失效并删除可删除的本地副本。

MVP 只创建一个 `Account`。业务用例仍使用稳定能力标识，例如：

```text
library.manage
task.confirm
organization.execute
integration.configure
system.configure
```

当前管理员拥有全部 MVP 能力。M4 增加家庭成员时可以增加能力映射，但 M1 不创建角色编辑、资源范围或权限管理界面。

### 12.2 会话与请求安全

- 密码使用 Argon2id，并在 M2 依据目标硬件校准参数。
- Web 使用同源、`Secure`、`HttpOnly` 和适当 `SameSite` 的会话 Cookie。
- 状态修改请求使用 CSRF 令牌或等价同源防护。
- 会话可吊销、有空闲与绝对期限，密码变化后撤销旧会话。
- 登录、初始化、敏感配置和恢复操作具有速率限制与审计。

### 12.3 连接器密钥

实例首次启动生成权限为 `0600` 的本地实例密钥文件。连接器凭据使用带认证加密保存到 SQLite；非敏感地址、能力和健康结果与密文分开。数据库备份和实例密钥备份分开管理，恢复时必须同时校验。

### 12.4 审计与脱敏

审计至少记录账号和会话变化、目标与规则配置、人工识别和分组决定、计划版本、文件操作、恢复、回滚、连接器配置和备份恢复。每条记录包含适用的 `actor_id`、`request_id`、`task_id`、`operation_id`、时间和稳定动作类型。

密码、令牌、Cookie、实例密钥、连接器密文和完整敏感配置不得进入日志、SSE、通知或诊断快照。面向管理员的文件路径按任务需要显示；通用日志和导出诊断优先保存根目录 ID 与相对路径。

## 13. 连接器与未来扩展

连接器按能力类型定义编译期端口：

| 能力端口 | MVP 实现 | 后续边界 |
| --- | --- | --- |
| `MetadataProvider` | TMDB 查询与健康 | 可以增加新的内置元数据适配器 |
| `ServiceHealthProvider` | Jellyfin 连接测试、健康和首页地址 | 不隐含媒体库、扫描或媒体映射能力 |
| `IdentificationEnhancer` | 无 | M4 增加一个可关闭的内置本地模型适配器 |
| `DownloadSource` | 无 | M4 才接入下载器和来源自动化 |
| `NotificationSink` | 无 | M4 才接入应用外通知 |

每个适配器声明能力、配置 schema 版本、超时、重试分类和健康结果。领域模块依赖能力端口，不依赖具体适配器类型。连接器调用使用有限超时、退避和错误分类；连接失败不得破坏目录主数据。

Jellyfin MVP 适配器不得声明或实现媒体库列表、映射、扫描、可见性验证或媒体级跳转。Jellyfin 健康检查在独立后台活动中运行，只更新 `IntegrationHealth`。

M4 的本地模型适配器只实现 `IdentificationEnhancer`，用于候选重排或非标准文件名信息提取。关闭、超时、失败或资源不足时必须退回确定性路径，不改变文件安全规则。MVP 不发布外部 provider SDK、动态库 ABI、WASI 插件或任意脚本执行器。

## 14. 部署与运行边界

MVP 保持一个 Core 进程和一个 OCI 容器：

```text
容器
├─ MediaFlow Core
├─ Vue Web 静态资源
├─ SQLite 与配置 /config
└─ ffprobe 子进程

挂载
├─ /config                         本地 SQLite 兼容卷
├─ /data/inbox/...                 部署授权收件根
└─ /data/media/...                 部署授权目标根
```

- 容器不使用特权模式，不要求 root，也不挂载整个 NAS 根目录。
- 部署者使用明确 UID/GID 和最小读写权限；Web 只能选择已经挂载的子目录。
- 移动策略需要来源删除权限，复制和硬链接按实际操作要求授权；权限不足时在预演或执行前暂停。
- Core 可以提供 Web 静态资源和本地健康端点；HTTPS、远程访问、VPN 和反向代理由用户部署环境负责。
- 首版不引入 Redis、RabbitMQ、Kafka、独立 Worker、外部工作流服务或必需云端控制面。
- `ffprobe` 使用参数数组和受控输入调用，不经过 shell；超时、输出大小和并行度有界。

## 15. 容量与性能预算

参考数据集是后续基准的测试输入，不是产品硬上限：

| 指标 | M1 目标 | 测量边界 |
| --- | ---: | --- |
| 文件记录 | 100,000 | 包含当前和历史可追踪文件记录 |
| 媒体项目 | 50,000 | 包含电影、剧集层级和通用视频成员 |
| 默认并行文件任务 | 最多 20 | 外部 HTTP、`ffprobe` 和文件 IO 使用独立更低配额 |
| Core 空闲 RSS | ≤ 150 MB | 启动稳定后，无活动任务 |
| 活跃扫描容器 RSS | ≤ 300 MB | 参考数据集、默认并发，包含 Core 管理的子进程 |
| 本地数据库列表 API p95 | ≤ 200 ms | 预热数据库、同主机、不含外部调用 |
| 普通本地写请求 p95 | ≤ 500 ms | 不含文件复制、`ffprobe` 或外部调用 |
| 提交后 SSE 可见延迟 p95 | ≤ 1 s | 从数据库提交到已连接客户端收到事件 |
| Web 首屏业务 JS gzip | ≤ 180 KB | 应用壳与首个业务路由，不含按需图表 |
| 1000 个未结束任务恢复调度 | ≤ 30 s | 无外部服务等待，完成租约回收和可运行任务重排 |

扫描、分页和事件投影必须使用流式或有界批处理，内存不得随目录总量线性增长。列表必须服务端分页，Web 大列表必须虚拟化，单任务事件不得触发完整列表刷新。

首次全量扫描耗时、网络文件系统延迟和媒体探测吞吐受硬件、挂载和文件组成影响。M2 必须记录参考硬件、文件系统、数据集和实际结果，不用脱离环境的固定扫描耗时作为产品承诺。

这些数值是 M1 设计预算，只有在相应模块初始化并执行实际基准后才能描述为“通过”。未达到预算时，正式 change 必须记录差异、原因和调整决定，不能静默放宽目标。

## 16. 风险与隔离验证

| 风险 | 当前控制 | 必须验证的阶段 | 失败处理 |
| --- | --- | --- | --- |
| 文件监听漏事件或事件风暴 | 监听只优化延迟，周期对账负责正确性 | M2 | 降低监听权重，保留对账 |
| SQLite 位于不兼容网络文件系统 | `/config` 要求本地 SQLite 兼容卷 | M2 | 启动检查失败并给出迁移建议 |
| 路径逃逸、符号链接和竞态 | 能力目录、执行前复核、不覆盖创建 | M2/M3 | 任何不确定状态安全暂停 |
| 重启导致重复任务或事件 | 稳定 ID、租约、检查点和幂等消费 | M2 | 保留原任务并报告冲突证据 |
| NAS 文件系统的移动、硬链接和落盘语义差异 | 按挂载能力执行真实验证 | M3 | 禁用不可靠操作，不静默降级 |
| 文件操作与数据库检查点不一致 | journal 与实际文件核对 | M3 | 进入恢复或人工处理 |
| 管理员初始化被抢占 | 部署侧一次性引导密钥 | M2 | 不开放无密钥远程初始化 |
| SQLite 单写者争用 | 短事务、有界 Worker、分页和投影 | M2/M3 | 优化写入边界；不提前换数据库 |
| 通用视频扩张成课程系统 | 最小分组和成员模型 | M3 | 新领域需求建立独立 change |
| Jellyfin 能力反向进入任务 | 类型化能力和禁止映射不变量 | M3 | 拒绝不在能力声明中的调用 |
| 本地模型成为必需依赖 | 可选 `IdentificationEnhancer` 与确定性回退 | M4 | 禁用适配器并保留基础闭环 |

### 16.1 M2 必须优先完成的隔离验证

1. SQLite WAL、迁移、升级前备份和干净实例恢复。
2. 能力目录、符号链接、规范化路径、权限不足和越权路径。
3. 持久扫描任务、租约过期、Core 重启和重复发现复用。
4. outbox、SSE 断线恢复、`Last-Event-ID` 和至少一次交付去重。
5. 一次性管理员初始化、Argon2id 校准、安全 Cookie 和会话吊销。
6. 10 万文件与 5 万媒体项目数据集上的索引、分页、内存和 API 基准。

上述验证必须进入 M2 的 `mediaflow-full` change 和实际测试，不在 M1 用静态文档声称运行通过。

## 18. M2 交接

M1 整体验收前不开始生产编码。M2 必须先创建 `mediaflow-full` 实现型 change，并按当时官方状态重新核对 Rust、Axum、Vue、Vite、SQLite 和契约工具。

