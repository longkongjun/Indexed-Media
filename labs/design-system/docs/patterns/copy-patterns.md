# 交互模式 · 文案模板与术语（copy-patterns）

> 版本：v1.0 ｜ 基准：web-experience §7 错误文案模板（对象+原因+下一步）+ governance/glossary 术语表。
> 全部界面文案的模板与禁区；三端共用同一词表（跨端契约）。

## 1. 错误文案三要素模板

```text
「{对象}在{阶段}失败：{原因摘要}。下一步：{动作}。」
```

- **对象**：任务 ID（task-1042）或相对路径——安全标识，可用等宽体。
- **原因**：对齐 Core 稳定错误码的人话语义（conflict → "目标路径已存在"）；括注错误码 `(conflict)` 供诊断。
- **下一步**：来自该状态的恢复动作词（recovery-actions 总表主操作词），可点击。
- 示例：「task-1042 在文件操作阶段失败：目标路径已存在（conflict）。下一步：修正规则或目标后重新计算计划。」

## 2. 各态文案模板

| 态 | 模板 | 示例 |
|---|---|---|
| Empty（列表） | "暂无{对象}。{为何为空的一句话}。" + 主操作 | "暂无正式媒体记录。完成待确认任务后即可建立。" |
| Empty（筛选） | "没有匹配{筛选条件}的结果。" + 清除筛选 | — |
| Offline | "无法连接 MediaFlow 服务。正在显示{时间}的数据。" + 重试 | — |
| Conflict | "{对象}与{已存在对象}冲突：{冲突点}。" + 修正入口 | — |
| Partial | "{N} 项已完成，{M} 项未完成：{未完成摘要}。" + 只重试未完成 | — |
| Success | "{对象}已完成：文件整理、NFO 与媒体记录均完成。" | — |
| 确认对话（破坏性） | "将{动作}{对象}。{不可自动撤销/可回滚说明}。" | — |

## 3. 禁区

1. 不出现凭据、令牌、完整宿主路径（脱敏规则同 session-message）。
2. 不用"出错了/系统繁忙/未知错误"泛化文案——必须落到对象与错误码语义；确实未知时"未知错误（{code}）+ 反馈入口"。
3. 不用指责性表述（"你的输入有误"→"该路径不在授权范围内"）。
4. 不用感叹号与拟人化道歉（"哎呀/抱歉啦"）；一句"无法完成 X"足矣。
5. 不把硬链接失败表述为"移动"（操作类型如实）。

## 4. 术语对齐

- 界面状态与动作词以 wiki 术语表为准；本设计系统新增词汇入共享字典（TYPE_LABELS 类），三端同源。
- 核心动作词表（不做同义变体）：重试 / 重新计算计划 / 修正规则 / 确认候选 / 转为通用视频 / 批准 / 拒绝 / 隔离 / 回滚。
- 状态词表与 status-badge 词表一致：完成、成功、待确认、部分成功、降级、失败、冲突、运行中、排队、未开始、已停用、跳过。

## 5. 语言与格式

- 简体中文；数字与 ID 用半角；时间相对格式（"3 分钟前"）+ title 绝对时间；路径/代码/ID 一律等宽体。
- 句式：陈述句、句号结尾、一句话一件事；按钮文案动词开头（"重新计算计划"而非"计划的重新计算"）。
