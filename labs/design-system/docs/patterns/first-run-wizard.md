# 交互模式 · 首次配置向导（first-run-wizard）

> 版本：v1.0 ｜ 基准：web-experience §5 首次配置顺序 + web-prototype 五步向导先例。
> 管理员首次进入的引导流：只验证配置和连接，不移动文件。

## 1. 步序（固定，不可跳序；可中断续配）

```text
① 管理员账号（setup，现状已有） 
② TMDB 连接（元数据源，必配）
③ 收件目录（授权路径 + 连通性检查）
④ 资源库与整理目标（电影/剧集库 + 通用视频目标）
⑤ 规则（命名/NFO/自动执行条件）
⑥ 权限与连接检查（汇总体检）→ 进入概览
```

Jellyfin / DSH / 下载器为**非必需**，向导内只提示"可在设置中后续配置"，不设步骤。

## 2. 每步模板

```text
[步骤指示器] ①—②—③—④—⑤—⑥（当前步高亮，已完成 ✓，可点回退）
[步骤标题 + 为什么需要这一步（一句话）]
[表单（form 规格）]
[步内验证]：失焦校验 + "测试连接/检查路径"按钮（实时反馈，不等到最后）
[底部] 上一步(secondary) · 下一步(primary，验证通过才可用)
```

## 3. 行为规则

- 每步完成即保存（服务器端）；中断后重进从首个未完成步开始；已完成步可回退修改（下游步骤如受影响给提示）。
- 步 ⑥ 体检表：每配置项一行（检查项/结果徽章/失败时修复链接）；全部通过才亮"进入概览"。
- 全程不出现文件操作；文案明示"本向导只验证，不移动任何文件"。
- 路径配置即时检查：授权边界外路径当场拒绝（表单错误态），不积压到体检。

## 4. 空系统进入概览后

概览 Empty/引导态：给"下一步"指引（扫描收件目录 → 查看待确认），复用 state-container Empty（说明为何为空 + 一个明确下一步）。

## 5. 平台差异

向导为 Web 独有（管理面）；移动端无向导（首批无管理员功能）；TV 无。
