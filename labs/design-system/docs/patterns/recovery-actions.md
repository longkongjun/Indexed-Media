# 交互模式 · 恢复动作（recovery-actions）

> 版本：v1.0 ｜ 基准：web-experience §4 恢复动作表（方案正源），本文件将其升格为可复用交互模式。
> 铁律：**每个状态 → 一个展示重点 → 一个唯一主操作**；次要动作可见但不竞争。

## 1. 模式结构

```text
[状态徽章（双编码）] + [展示重点区] + [主操作 Button(primary)] + [次操作 link/secondary ×≤1]
```

## 2. 状态映射总表（对齐 Core 语义）

| 状态 | 展示重点 | 唯一主操作 | 次操作 | Core 语义锚 |
|---|---|---|---|---|
| 待确认 | 候选、置信度、依据、原文件未变 | 选择候选/修正/转通用视频 → 重算计划 | 查看原文件信息 | review case |
| 冲突 | 来源、目标、规则缺口/已存在文件 | 修正规则或目标 → 重算计划 | 查看冲突详情 | 409/conflict 错误码 |
| 失败 | 失败阶段、已产生结果、未执行动作 | 从安全检查点重试 | 查看时间线 | task error + journal |
| 部分成功 | 已完成与未完成的本地步骤 | 只重试未完成步骤 | 保留结果查看 | partial-success |
| 等待审批 | 计划摘要 + 版本 | 查看完整计划并审批 | 稍后（收起到通知） | needs_approval |
| 离线 | 全局横幅 + stale 数据可读 | 重连/重试 | — | 网络层错误 |

## 3. 重试语义（不可违反）

1. 重试**不重复执行**已安全完成的整理（安全检查点语义由 Core journal 保证，UI 只呈现"将重试：N 项未完成"清单）。
2. 任何界面不得把硬链接失败静默改为复制/移动（展示实际操作类型，见 plan-preview 反例）。
3. 不提供绕过授权路径的"强制继续"。
4. 重试入口在失败上下文内（时间线/详情/横幅），不在列表行全局批量（批量重试属 P5+ 需求，未定义前不做）。

## 4. 流程模板

```text
失败发现 → state-container(Error, stale) 或时间线问题节点默认展开
  → 管理员读：对象+原因+已产生/未执行（三段式）
  → 主操作"从检查点重试" → 二次确认（幂等说明）→ Loading(stale)
  → 成功：Success 确认（明确"文件操作、NFO、记录均完成"）或部分成功 → 递归本模式
```

## 5. 文案连接

错误文案走 copy-patterns 三要素模板（对象+原因+下一步）；下一步 = 本表主操作词，词表一致（"重试/重算计划/修正规则"），不使用同义变体（"再试一次/重新执行"）。

## 6. 平台差异

Web 全量；移动端（M5）只读呈现 + 取消类安全操作，恢复动作跳 Web 完成或第二批评估；TV 不承载恢复（只读消费）。
