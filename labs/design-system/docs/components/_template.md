# 组件规格统一模板

> 所有组件规格文档（docs/components/*.md，_template/index 除外）必须按本模板的章节与顺序撰写，保证人读体验一致。章节可因组件不适用而省略，但不可改序、不可改名。

```markdown
# <组件名>（<slug>）

> 版本：v<_semver> ｜ 状态：草案｜定稿 ｜ 来源：现有提取（<现有文件/类名>）｜新功能规格
> 一句话职责。

## 1. 解剖
结构分解（元素树或分区图）+ 每区引用的 token（不写死数值）。

## 2. 状态 × 变体矩阵
表格：变体（尺寸/形态）× 状态（默认/hover/active/focus-visible/disabled/加载…）。
双主题成立性：矩阵对浅色与暗色均成立；主题敏感点在此标注 🔆（指向 §5）。

## 3. 行为与交互
事件语义、加载与延迟行为、数据边界（空/超长/截断规则）。

## 4. 可访问性
- 键盘路径（Tab/Enter/Space/Arrow/Esc 逐一列）
- 焦点行为（focus-visible 样式、焦点陷阱、roving tabindex）
- ARIA（role/aria-* 具体值）
- 对比度（引用 tokens.json contrast_pairs 对名；边框须声明分级：识别边界/装饰）
- 状态不单靠颜色（图标/形状/文字双编码要求）

## 5. 主题表现（🔆 主题敏感组件单列；不敏感者可省略）
暗色下与浅色的差异点与原因（引用 dark-media-principles 章节号）。

## 6. 用法与反例
✅ 正确用法 2-3 条；❌ 反例 2-3 条（含为什么）。

## 7. 平台差异
| 维度 | Web | Compose（M3） | SwiftUI |
组件在该三端的实现要点与映射表引用（docs/mappings/）。

## 8. 变更记录
- v<版本>：<变更摘要>（破坏性变更须标 ⚠ 并同步 manifest.json breaking_changes）
```

模板一致性检查项（D2 出口执行）：
1. 章节顺序与命名与模板一致；
2. 全文无硬编码颜色/尺寸数值（hex、px、rem）——一律 `token 名`（引用格式 `--mfd-*` 或语义名）；
3. 每个规格有版本号与来源标注；
4. 状态×变体矩阵明确"双主题均成立"或标注 🔆 并有 §5；
5. 可访问性章节四要素（键盘/焦点/ARIA/对比度）齐全，边框声明分级；
6. 平台差异表三列齐全（允许"同 Web"简写）。
